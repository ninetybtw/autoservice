# Запись в автосервис

Готовое веб-приложение для онлайн-записи в автосервис. Открывается по обычной ссылке
на телефоне и компьютере, без регистрации и установки. Его можно добавить на главный
экран телефона: тогда оно открывается без адресной строки, со своей иконкой и названием студии.

Одно развёртывание обслуживает сколько угодно автосервисов: у каждого своя ссылка
`https://<сайт>/<slug>` и свой кабинет владельца `https://<сайт>/<slug>/admin`.

## Что умеет

**Клиент**
- главная: большое фото, название, описание, три карточки преимуществ, услуги с ценами,
  фото работ, адрес, «как найти», время работы, заметная карточка «Запись»;
- запись: услуга → дата → свободное время (занятое отмечено «занято») → имя, телефон, машина → подтверждение;
- «Моя запись»: подробности, отмена по правилам студии, напоминание за сутки (push),
  а где push недоступен — файл для календаря `.ics` и Google Календарь;
- помощник: «Когда ближайшее окно?», «Сколько стоит полировка?», «Как найти студию?» —
  отвечает по услугам и расписанию этой студии и задаёт уточняющий вопрос, если данных не хватает;
- работает без сети там, где это возможно: страница автосервиса, услуги и своя запись открываются из кэша.

**Владелец** (вход по почте и паролю)
- записи на день и неделю, число записей, заездов, готовых работ и реально полученные деньги;
- ручная запись, перенос, отмена, «Машина принята», «Готово», «Не приехал», оплата и возврат;
- услуги, цены, длительность, часы работы, выходные и особые дни, адрес, телефон, логотип, главное фото,
  три карточки на главной, правила записи (боксы, подготовка, отмена);
- фото работ: добавить карточку, заменить конкретное фото, изменить подпись — остальные работы не трогаются;
- помощник: «Что у меня завтра?», «Сколько машин было на неделе?», «Сколько денег получено?».

### Как считается свободное время
`shared/slots.ts`, покрыто тестами `tests/slots.test.ts`:
- по графику автосервиса в его часовом поясе (`date-fns-tz`), с учётом особых дней;
- по каждому посту (боксу) отдельно: время свободно, если свободен хотя бы один пост;
- длительность услуги — рабочее время; после работы пост занят ещё на время подготовки;
- услуга длиннее рабочего дня продолжается в следующие рабочие дни, а пост занят все эти дни
  (включая ночь); начать её можно в первой половине дня;
- на сервере время перепроверяется, а пересечения на одном посту запрещены ограничением
  `bookings_no_overlap` в Postgres — двойная запись невозможна даже при одновременных запросах.

## Быстрый старт (без сервера)

```bash
pnpm install
pnpm dev            # http://localhost:5173/motor-service
```

Без переменных Supabase приложение работает в **демо-режиме**: автосервисы берутся из папки `studios/`,
записи и оплаты хранятся в браузере. Кабинет: `/motor-service/admin`,
почта `owner@motor-service.ru`, пароль `demo1234`.

## Новый автосервис за несколько минут

Все данные автосервиса — в одном файле `studios/<slug>/studio.json`, фото лежат рядом.
Редактор подсказывает поля и проверяет файл по схеме (`studios/studio.schema.json`).

```bash
pnpm studio:new avto-pro "Авто Про"   # папка из шаблона + временные фото
# 1. Заполните studios/avto-pro/studio.json: название, цены, адрес, телефон, график, почту владельца
# 2. Замените hero.jpg, logo.svg, work-*.jpg своими фото (имена файлов — как в studio.json)
pnpm dev                                         # проверьте http://localhost:5173/avto-pro
pnpm studio:push avto-pro                   # публикация в Supabase
```

`studio:push` проверит файл, загрузит фото в хранилище, создаст автосервис и вход владельца и напечатает:

```
✓ Автосервис «Авто Про» опубликован
  Ссылка для клиентов: https://<сайт>/avto-pro
  Кабинет владельца:   https://<сайт>/avto-pro/admin
  Логин:               owner@avto-pro.ru
  Пароль:              …
```

Фото можно указать файлом из папки или ссылкой (`https://...`). Для ссылки стоит добавить запасной файл —
`heroFallback` для главного фото и `fallback` для работы: если ссылка не откроется, покажется он.
В демо-сервисах стоят бесплатные фото с Unsplash, их стоит заменить настоящими фото самого сервиса.

Дальше владелец меняет данные сам в кабинете. Повторный `studio:push` для уже опубликованного
автосервиса требует `--force` (правки владельца будут перезаписаны). Новый пароль: `--password=...`.

## Публикация (один раз)

### 1. Supabase
1. Создайте проект на supabase.com.
2. Примените миграции: `npx supabase@latest link --project-ref <ref>` и `npx supabase@latest db push`
   (или выполните `supabase/migrations/*.sql` в SQL Editor).
3. Секреты функций:
   ```bash
   npx supabase@latest secrets set OPENAI_API_KEY=sk-... OPENAI_MODEL=gpt-5-mini \
     VAPID_PUBLIC_KEY=... VAPID_PRIVATE_KEY=... VAPID_SUBJECT=mailto:you@example.com \
     CRON_SECRET=<случайная строка> APP_URL=https://<сайт>
   ```
   VAPID-ключи: `npx web-push generate-vapid-keys`.
4. Функции: `pnpm functions:deploy` (копирует общую логику из `shared/` и публикует `booking`, `assistant`, `send-reminders`).
5. Напоминания за сутки: выполните `supabase/cron.sql` (подставьте адрес проекта и `CRON_SECRET`).
6. В Authentication → Providers → Email отключите самостоятельную регистрацию — владельцев создаёт `studio:push`.

### 2. Vercel
Импортируйте репозиторий (фреймворк Vite, pnpm подхватится сам) и задайте переменные:
`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_VAPID_PUBLIC_KEY`.
Функция `api/manifest.ts` отдаёт каждому автосервису свой манифест: название и иконку для главного экрана.

### Модель помощника
Модель меняется секретом `OPENAI_MODEL` на сервере — без пересборки приложения
(для совместимых API есть `OPENAI_BASE_URL`). Помощник вызывает инструменты с данными автосервиса
(`shared/assistant/tools.ts`), поэтому отвечает только по его услугам, расписанию, записям и оплатам.
Без `OPENAI_API_KEY` или при ошибке модели работает встроенный помощник без модели
(`shared/assistant/fallback.ts`) — он тоже понимает примеры вопросов и задаёт уточняющие.

## Стеклянный эффект и анимации

`src/components/LiquidGlass.tsx` — обёртка над liquid-gl.
- Стекло — отдельный слой под надписью; надпись остаётся обычным текстом и всегда чёткая (`content: false`).
- Кнопка «Записаться» на главном фото преломляет только само фото (`snapshot: '.hero-media'`),
  поэтому при прокрутке в ней не появляются буквы соседних разделов. Она прокручивается вместе с фото.
- Нижняя панель — матовое тёмное стекло без бликов: сильное размытие, текст под ней не проступает.
- Снимок фона для стекла — тяжёлая операция, поэтому он обновляется только в паузе, когда прокрутка остановилась:
  во время прокрутки и анимаций главный поток свободен.
- Разделы появляются мягко и каскадом, страницы — с плавным переходом, подсветка в нижней панели скользит
  между пунктами.
- Без WebGL библиотека переходит на CSS `backdrop-filter`. При «Уменьшить движение» анимации отключены.

## Удобство и доступность

Интерфейс проверен по правилам скилла UI/UX Pro Max (`.claude/skills/ui-ux-pro-max`) и axe-core:
- цвета: чёрный фон, белый текст, мягкий кирпично-красный акцент `#C44A46` (белый текст на нём — 4,76:1)
  и коралловый `#EF8A80` для красного текста на чёрном (8,6:1);
- на сенсорных экранах все кнопки и поля не меньше 44×44 px;
- единые токены движения в `src/styles/global.css` (`--dur-*`, `--ease-*`): мягкие кривые без рывка и перелёта,
  разделы проявляются за ~0,65 с со сдвигом 8 px каскадом по 60 мс, страницы сменяются только проявлением;
  при «Уменьшить движение» анимации выключены;
- ссылка «Перейти к содержимому», перенос фокуса на новую страницу, фиксированная панель не закрывает элемент в фокусе;
- отступы под вырез экрана iPhone, шкала шагов записи, скелетоны вместо крутилок, подтверждение отмены записи.

`e2e/a11y.spec.ts` проверяет ключевые экраны на нарушения WCAG 2.2 AA и размер кнопок на телефоне.

## Проверки

```bash
pnpm typecheck      # TypeScript
pnpm test           # Vitest: расчёт времени, помощник, схемы, файлы автосервисов
pnpm test:db        # SQL-миграции на локальном PostgreSQL: пересечения, доступ, хранилище
pnpm test:e2e       # Playwright: путь клиента и владельца на телефоне и компьютере (демо-режим)
```

Если браузеры Playwright не скачаны, укажите свой Chromium: `PW_CHROMIUM=/path/to/chrome pnpm test:e2e`.

## Структура

```
studios/<slug>/studio.json   настройки автосервиса + фото рядом
shared/                      общая логика: схема (Zod), расчёт времени, правила, помощник
src/                         приложение (React)
  data/                      Supabase и демо-режим, хуки TanStack Query
  pages/admin/               кабинет владельца
  sw.ts                      service worker (Workbox): офлайн и push
api/manifest.ts              манифест PWA для каждого автосервиса (Vercel)
supabase/migrations/         схема БД, доступ (RLS), хранилище
supabase/functions/          booking, assistant, send-reminders (Deno)
scripts/                     studio:new, studio:push, проверки
e2e/, tests/                 Playwright и Vitest
```
